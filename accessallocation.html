ACCESS Project Allocations

Overview

Access to the BIL ecosystem is managed through ACCESS allocations. To be added to the BIL system and to maintain ongoing access, users must be associated with an ACCESS project that includes BIL as an allocated resource.

Allocations are governed by ACCESS policies:

  • Allocation policy: https://allocations.access-ci.org/allocations-policy
  • How to request an allocation: https://allocations.access-ci.org/how-to

Transition

All users must create an ACCESS project that includes BIL as a resource to continue using BIL after September 2026.

Users who do not complete this process by the deadline will temporarily lose access to BIL systems until an allocation is approved.

Beginning in September of 2026, all BIL users will be required to create an ACCESS Project and add BIL as an allocation of that project in order to maintain access to the BIL Submission Portal and Analysis Ecosystem.

Overall steps to this process:

  1. Log in to https://allocations.access-ci.org/ with the same credentials you used to create your BIL user.
  2. Request a new ACCESS Project, or identify the existing ACCESS Project that will utilize BIL
  3. Add BIL as a resource to your project and exchange credits for use at BIL.

Allocations

You can add multiple users to a single allocation. If there is a need to share data pre-submission and have multiple users access the same data pre-publication, those users should coordinate to be on the same allocation.

Requesting a Project Allocation

  1. If you have not already, create an account and gain access to the BIL Portal, as described here: https://www.brainimagelibrary.org/account.html
  2. Log in to the ACCESS Allocations Dashboard: https://allocations.access-ci.org/
  3. Request a new "Explore" ACCESS Project
  4. Complete the form. You will receive an email notification confirming your successful request. Once a decision has been made, you will receive a separate notification.

Exchange Credits

After you have requested an allocation, you will need to exchange the credits for resources. Below is a short guide, but for detailed instructions on allocations, please see: https://allocations.access-ci.org/how-to

  1. First, login to​ allocations.access-ci.org

    • You’ll see your project information, or a list of your projects if you have multiple.

  2. Click on the “Credits + Resources” tab.

    • You can request multiple resources within one exchange.

  3. Click “Add a resource to your exchange.”

    • The list of available resources will then populate. You can find BIL under the "Storage Resources" section.

  4. Select a resource.

    • A required resource (oftentimes a storage resource) will automatically populate along with your selection.

  5. Enter the amount of units you’d like to request.

    • Request the amount storage that you anticipate using for your project.

  6. Enter a brief justification of why you’re requesting the resource(s).

  7. Click “Submit for Approval.”

    • A pop-up will then appear to “Complete Your Exchange.”

  8. Confirm the amounts being requested are correct, then click “Submit.”

    • You will receive an email notification confirming your successful request. Once a decision has been made, you will receive a separate notification.

Key Terms

ACCESS

ACCESS (Advanced Cyberinfrastructure Coordination Ecosystem: Services & Support) is a national program that provides researchers with access to shared cyberinfrastructure resources, including computing, storage, and data services. BIL participates in this ecosystem and uses ACCESS to manage user access and resource allocations.

ACCESS Allocation

An ACCESS Allocation is the approval that allows a project to use specific ACCESS-managed resources. Allocations are tied to an ACCESS project and define:

  • Which resources can be used (e.g., BIL storage)
  • How much of each resource is available
  • Which users are allowed to access them

Users must be associated with an active allocation to use BIL services.

ACCESS Project

An ACCESS Project is the organizational container for one or more related research efforts within ACCESS. Each project:

  • Has a Principal Investigator (PI)
  • Can include multiple users
  • Can request one or more allocations (resources)

For BIL access, users must belong to an ACCESS project that includes BIL as a resource.

ACCESS Resource

An ACCESS Resource is a specific service or infrastructure component made available through ACCESS. Examples include:

  • High-performance computing systems
  • Data storage systems
  • Specialized data platforms such as BIL

Adding BIL as a resource to your ACCESS project enables project members to store, submit, and analyze data within the BIL ecosystem.

Frequently Asked Questions (FAQ)

Do I need an ACCESS project if I already have a BIL account?

Yes. After September 2026, all BIL users must be associated with an ACCESS project that includes BIL as a resource, even if they already have a BIL account.

Can multiple users share the same ACCESS project and allocation?

Yes. Multiple users can be added to a single ACCESS project and allocation. This is recommended for teams that need to share data or collaborate within BIL before publication.

Do I need a new ACCESS project for every grant?

Not necessarily. An eligible PI may:

  • Create one ACCESS project per supporting grant, or
  • Combine closely related work from multiple grants into a single ACCESS project

What happens if my ACCESS allocation expires or is not approved?

If your project does not have an active allocation that includes BIL, access to BIL systems will be temporarily disabled until an allocation is approved.

Who should request the ACCESS project and allocation?

To qualify to lead (serve as Principal Investigator) an allocated project, you must be a U.S-based researcher or educator, at the graduate-student level or higher. Typically, the Principal Investigator (PI) submits the ACCESS project request and allocation. Once approved, additional users can be added to the project. The PI of an allocated project can be but does not need to be the PI for the supporting grant.
