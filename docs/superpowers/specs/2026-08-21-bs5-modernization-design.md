# BIL Info Site — Bootstrap 5 Modernization + Live Stats

**Date:** 2026-08-21
**Status:** Design (awaiting implementation-plan phase)
**Site:** `www.brainimagelibrary.org` (GitHub Pages)
**Repo:** `bil_info_site/bil_info_site`

## Goal

Modernize the static HTML site with two coupled changes:

1. Migrate the site from Bootstrap 4 + jQuery + Font Awesome 4.7 to Bootstrap 5.3.3 + Bootstrap Icons, with a small custom design system layered on top so the site has its own visual identity rather than a bare-framework look.
2. Add a live-looking stats block to the landing page that surfaces the numbers already exposed by `https://api.brainimagelibrary.org/stats?type=all` (dataset count, species distribution, modality distribution).

All existing page content is preserved. Nav structure is preserved. Only `datasets.html` (a 4.6 MB orphaned artifact with zero inbound links) is deleted.

## Constraints and background

- **Hosting:** GitHub Pages. No backend, no server-side runtime under our control.
- **CORS:** `api.brainimagelibrary.org` does not currently send `Access-Control-Allow-Origin`. A browser at `www.brainimagelibrary.org` cannot fetch from `api.brainimagelibrary.org` directly. The user can change nginx on the API VM but is not doing so as part of this project.
- **Content review is out of scope.** Nav links and page inventory stay as-is. A separate content-review pass to prune retired/dead pages is a follow-up the user will run with their team.
- **Existing precedent for BS5:** The API's own `/web/search.html` (iframed on today's homepage) already uses Bootstrap 5.3.2. There is no cross-team coordination cost to adopting BS5.

## Summary of decisions

| Area | Decision |
|---|---|
| Site build | Jekyll on GitHub Pages (native — no extra CI) |

| Stats data source | Static `data/stats.json` in the repo, regenerated by GitHub Actions on daily cron from `/stats?type=all` |

| API failure mode | Workflow exits non-zero, `stats.json` untouched, previous good data continues to serve |

| Deletions | `datasets.html` only. Nav unchanged. Orphan pruning is a follow-up |

## 2. Design system

### 2.1 CSS strategy

Bootstrap 5.3.3 from jsDelivr, plus a single hand-authored `assets/css/site.css` that layers our design tokens and components on top. No Sass, no build step, no BS5 recompilation. BS5.3 exposes its theme as CSS custom properties (`--bs-primary` etc.), so overriding is a `:root` block, not a Sass rebuild. This keeps future maintenance simple — anyone who can read CSS can edit `site.css`.

### 2.2 Design tokens (`assets/css/site.css` top block)

```css

  --bil-primary-deep: #0f2f4c;
```

- Body: system-ui stack, weight 400, 16 px, line-height 1.55.
- Only three Inter weights loaded (400/600/800) to keep the font payload small.

## 4. Stats pipeline

### 4.1 GitHub Action `.github/workflows/stats.yml`

```yaml
name: Refresh stats.json
on:
  schedule:
    - cron: "0 6 * * *"       # 06:00 UTC daily
  workflow_dispatch: {}

permissions:
  contents: write

jobs:
  refresh:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }
      - run: pip install requests
      - run: python3 scripts/build_stats.py
      - name: Commit if changed
        run: |
          if ! git diff --quiet data/stats.json; then
            git config user.name  "stats-bot"
            git config user.email "stats-bot@users.noreply.github.com"
            git add data/stats.json
            git commit -m "chore(stats): daily refresh"
            git push
          fi
```

On API failure, `build_stats.py` exits non-zero. The commit step never runs. `data/stats.json` retains its previous contents. The workflow run shows red in GitHub; email notification alerts the user.

**Note on the automated `git push` inside this workflow:** the user's "no pushing" instruction applies to human-driven commits for the modernization work itself. The `stats-bot` push above is the *runtime* behavior of the workflow after it lands — the mechanism the user explicitly chose when picking the GH-Action static-JSON option. The workflow YAML itself is code we commit locally like any other file; the user reviews and pushes it as part of the modernization PR.

### 4.2 `scripts/build_stats.py`

Responsibilities:
1. `GET https://api.brainimagelibrary.org/stats?type=all` with a 15 s timeout.
2. Validate the payload contains `dataset_count`, `species`, `modalities`, `consortiums` keys. Exit non-zero if not.
3. Filter modalities: drop any entry with `name` in `{"#N/A"}` or `count == 0`.
4. Apply the species merge table (see 4.4). Log every merge to stdout so the workflow log is auditable.
5. Sort species and modalities descending by count.
6. Compose the output document (see 4.3). Write with `indent=2, sort_keys=False, ensure_ascii=False`.
7. Write to `data/stats.json` atomically (write temp, `os.replace`).

### 4.3 `data/stats.json` schema

```json
{
  "generated_at": "2026-08-21T06:00:14Z",
  "source": "https://api.brainimagelibrary.org/stats?type=all",
  "headline": {
    "datasets":   14225,
    "consortia":  4,
    "species":    14,
    "modalities": 14
  },
  "species": [
    { "name": "Mouse", "count": 12178 }
  ],
  "modalities": [
    { "name": "Cell morphology", "count": 5282 }
  ],
  "consortia": [
    { "label": "Brain Initiative Cell Census Network (BICCN)",
      "value": "BICCN",
      "count": 10960 }
  ]
}
```

Species and modalities are pre-sorted descending by count. Species names use the canonical form from the merge table (§4.4); unmerged species pass through with title-case applied (`"crab-eating macaque"` → `"Crab-eating macaque"`). Modality names use title-case from the raw endpoint. `#N/A` and zero-count entries are dropped. `headline.species` and `headline.modalities` are the *post-filter, post-merge* counts.

### 4.4 Species merge table

```python
# Canonical display name -> raw endpoint names to fold in
SPECIES_MERGE = {
    "Mouse":                ["mouse"],
    "Human":                ["human", "homo sapiens"],
    "Rhesus macaque":       ["rhesus macaque", "macaca mulatta"],
    "Pig-tailed macaque":   ["pig-tailed macaque", "macaca nemestrina"],
    "Common marmoset":      ["common marmoset", "marmoset"],
    "Crab-eating macaque":  ["crab-eating macaque"],
    "Squirrel monkey":      ["saimiri sciureus", "squirrel monkey"],
    "Macaque (unspecified)":["macaque"],
    "Rat":                  ["rat"],
    "Fruit fly":            ["fruit fly"],
    "Clonal raider ant":    ["clonal raider ant", "ooceraea biroi"],
    "Zebrafish":            ["zebrafish"],
    "Sea squirt":           ["ciona robusta"],
    "Spider":               ["spider", "feather-legged spider"],
}
```

Unrecognized raw names pass through under their raw display name and are logged so the user notices new taxonomy entries.

### 4.5 Frontend `assets/js/stats.js`

Dependency-free. Loads on `DOMContentLoaded`. Fetches `data/stats.json` with `cache: "no-store"` (cache-busting is essential because GH Pages CDN aggressively caches, and the JSON is rewritten daily). Renders headline numbers into the pre-existing skeleton in `_includes/stats-block.html`, then renders bar rows into `#bil-species-bars` and `#bil-modality-bars` by string-composition (no template lib).

On error:
- `console.warn` the error
- Add class `bil-stats--unavailable` to the container, which CSS uses to swap the visible content to `Stats temporarily unavailable — visit the search page →`

## 5. Per-page conversion

### 5.1 The per-page transform

Every existing `*.html` file gets its `<html>`, `<head>`, `<body class="bg">`, nav-loader `<div>`, footer-loader `<div>`, and trailing script tags stripped. What remains is the page body (the current `.jumbotron.pagejumbotron` and its content, or equivalent). Jekyll front matter is prepended:

```html
---
layout: default
title: About BIL
---
```

The layout template supplies everything else.

### 5.2 BS4 → BS5 class rewrites

Applied by `scripts/bs4_to_bs5.py` using BeautifulSoup, so the rewriter walks class attributes and `data-*` attributes only — never text nodes. This protects `<pre>`/`<code>` samples on `metadataapi.html` from spurious rewrites.

| BS4 | BS5 |
|---|---|
| `data-toggle=` | `data-bs-toggle=` |
| `data-target=` | `data-bs-target=` |
| `data-dismiss=` | `data-bs-dismiss=` |
| `data-parent=` | `data-bs-parent=` |
| `data-slide=` / `data-slide-to=` | `data-bs-slide=` / `data-bs-slide-to=` |
| `.jumbotron` | replaced with `.hero` (index) or `.content-card` (all others) |
| `.text-left` / `.text-right` | `.text-start` / `.text-end` |
| `.ml-*` / `.mr-*` | `.ms-*` / `.me-*` |
| `.pl-*` / `.pr-*` | `.ps-*` / `.pe-*` |
| `.float-left` / `.float-right` | `.float-start` / `.float-end` |
| `.form-row` | `.row .g-2` |
| `.form-group` | dropped, `.mb-3` on the child |
| `.custom-select` | `.form-select` |
| `.custom-control.custom-checkbox` / `custom-radio` | `.form-check` |
| `.form-control-file` | `.form-control` |
| `.badge-primary` etc. | `.bg-primary .text-white` (color moved to bg utility) |
| `.close` | `.btn-close` |
| `.sr-only` | `.visually-hidden` |
| `.embed-responsive` | `.ratio` |
| `.no-gutters` | `.g-0` |
| `.font-weight-*` | `.fw-*` |
| `.font-italic` | `.fst-italic` |
| `.text-monospace` | `.font-monospace` |

After the automated pass, a manual per-page review pass follows because `.jumbotron` and `.form-group` replacements need judgement (the wrapper class matters for spacing).

## 7. Out of scope

Explicitly not in this PR (candidates for follow-ups):

- **Dark mode.** Design tokens are structured to support it; no dark styles are shipped.
- **"Most cited datasets" list** and **downloads world map** — parts of the coworker's mockup that require data not available from `/stats?type=all`. Needs new API fields or a separate data pipeline.
- **CORS enablement on the API side.** The user may add it later; when it lands, `stats.js` swaps one URL and the static JSON pipeline can be retired.
- **Content review / orphan pruning.** No pages are deleted except `datasets.html`. The user will run this pass with their team separately.
- **`datasets.html` replacement.** The page is deleted; users navigate to the API search UI (`/web/search.html`) which is what the index-page iframe already surfaces.
- **Sass build pipeline.** Not needed. If the design system grows enough to warrant it, a follow-up can introduce Sass with minimal churn.

## 9. Risks and open questions

- **CSS specificity conflicts between BS5 and `site.css`.** Mitigation: prefer CSS custom-property overrides to selector overrides. When a selector override is needed, prefix with `.bil-` and avoid `!important`.
- **`data/stats.json` cache staleness on GH Pages CDN.** Mitigation: `stats.js` uses `cache: "no-store"`. If GH Pages ignores this at the CDN layer, add a `?v=<generated_at>` cache-buster in `stats-block.html` (query string served by Jekyll from the JSON's `generated_at`).
- **Species merge table decisions.** Unrecognized species pass through and log; user will spot new taxonomy the first time a merge is needed. Not blocking.
- **`stats-bot` commits interleaved with human commits.** Daily automated commits to `master` are safe here because the workflow only touches `data/stats.json`. If review noise becomes an issue, move the JSON to a dedicated `stats` branch and use a GH Pages workflow to publish it — but that's overkill unless the daily commits become a problem in practice.
- **`bs4_to_bs5.py` false positives on `.jumbotron`/`.form-group`.** Mitigation: the script logs every rewrite, and the manual per-page pass in §5.2 catches judgement-calls.
- **Font loading FOUT.** Inter is loaded via Google Fonts with `display=swap` — brief flash of system-ui until Inter arrives. Acceptable.
